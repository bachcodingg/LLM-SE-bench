# Contributing

Thanks for looking. This is a research harness, so the bar for a change is
"does the number it produces still mean what it says it means".

## Before your first push

Run the security sweep. It is not optional and CI enforces it:

```bash
python scripts/security_sweep.py
```

It scans the working tree *and* the full git history for credential-shaped
strings, checks that no `.env` or SQLite cache is tracked, and verifies that
every environment variable the code reads is documented in `.env.example`.

If it finds a key in history: **rotate the key first.** Rewriting history
does not un-leak a credential that has already been pushed.

## Setup

```bash
git clone https://github.com/bachcodingg/LLM-SE-bench
cd LLM-SE-bench
pip install -e ".[dev,mcp]"
cp .env.example .env     # add keys only for providers you will call
```

Every test runs offline. The Docker sandbox falls back to a structural
dry-run when Docker is unavailable, and no test makes a real API call.

```bash
pytest -q
ruff check .
```

## Layout

The repository uses a flat package layout — one top-level package per
component — rather than `src/`. Each package is one of the five components
described in the README, and `contracts.py` is the only module they all
import from.

| Package | Component |
|---|---|
| `llm_gateway/` | C1 — provider clients, cache, cost, rate limiting |
| `bench/` | C2 — datasets, orchestrator, Docker sandbox |
| `quality/` | C3 — CK metrics, complexity, readability, refactoring |
| `stats/` | C4 — hypothesis tests, effect sizes, bootstrap |
| `framework/` | C5 — MCDA, recommender, dashboard, exporters |
| `mcp_servers/` | MCP tool layer over C1–C3 |
| `agent/` | The tool-calling agent loop and its trajectory table |
| `contracts.py` | Shared Pydantic models; the seam between components |
| `settings.py` | Every environment variable the project reads |

Tests live next to the package they cover (`bench/tests/`, …), with
cross-component tests in `tests/`.

## Rules that are actually load-bearing

**New shared data goes in `contracts.py`.** If two components need to agree
on a shape, it belongs there. A component that defines its own copy of
another component's model will drift.

**A new environment variable goes in `settings.py` and `.env.example`, in the
same change.** The sweep fails the build otherwise. Nothing else in the
codebase should call `os.environ` for configuration.

**Never commit results.** `results/`, `quality/`, `analysis/` and `reports/`
are generated. The single exception is `results/2026-05-run/`, the published
artifact, which is regenerated by `scripts/build_run_artifact.py` and never
edited by hand.

**Tests must not spend money.** If a test would make a real API call, it
needs a mock, a recorded fixture, or a skip. `MockLLMClient` exists for
single-shot evaluation and `agent.stub.StubAgentClient` for agent episodes.

**Anything that can spend money needs a ceiling before it can run.** The
agent loop refuses to start without `max_cost_eur`, and the MCP
`run_benchmark` tool refuses a non-dry run without a budget. Do not add a
default. There is no safe number to assume on someone else's account, and a
default is what turns "I ran the smoke test" into a bill.

**Never report an unexecuted result as a test result.** The Docker sandbox
falls back to a structural check that credits every `@Test` as passing.
Anything consuming that must carry the `executed` flag through and refuse to
call it a pass — `agent/termination.py` does this and there is a test
pinning it.

**MCP tool descriptions are prompts.** They are read by a model, not a
person. State preconditions, units and failure modes. A tool whose
description says "runs tests" and not "returns at most 200 lines of log,
truncated from the end, with `truncation.truncated` set" will be misused.

## Adding a dataset

1. Subclass `bench.datasets.base.Dataset` and implement the four abstract
   methods.
2. Put the task data in `data/<name>/` as JSONL.
3. Record where it came from in `data/PROVENANCE.md`, including the upstream
   licence. A task whose provenance is not written down cannot be published.
4. Register it in the `dataset_map` in `cli.py` and in
   `mcp_servers/tools/registry.py`.
5. Add it to `bench/tests/test_datasets.py` via `DatasetInterfaceTests`.

## Changing a prompt template

Prompt templates are inputs to a measurement. Changing one invalidates the
comparison against previously published numbers. If you change a template in
`llm_gateway/templates/`, say so in the PR and note which published results
it makes stale — `results/2026-05-run/manifest.json` records the SHA-256 of
every template as it was at run time, so the break is detectable.
